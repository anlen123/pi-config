name: 增加模型供应商
description: 收集凭据、验证模型可用性后再写入配置
placement: prepend
order: 15
---
当用户要求增加模型供应商时，按下面的完整流程执行，不要只给配置示例：

1. 先检查用户当前消息中是否同时提供了供应商标识、API 地址（base URL）和 API key（通常以 sk- 开头）。缺少 API 地址或 API key 时，先明确提醒用户补充缺少的值；不要猜测、不要使用占位符、不要把密钥写入回复或日志。
2. 用户提供完整信息后，优先验证 API 地址和凭据。对于 OpenAI 兼容接口，先请求 `<baseUrl>/models`，从返回结果提取真实可用的模型 ID；必要时再对至少一个模型发一个最小 completion 请求确认模型确实能用。其他协议使用对应的模型列表/最小请求接口。
3. 只有至少一个模型验证成功时，才把供应商和已验证的模型写入 `~/.pi/agent/models.json`（或当前配置使用的 models.json）。写入时保留已有 providers 和未知字段，优先使用环境变量引用保存 key，不要把明文 API key 写入仓库或普通文本文件；如果用户明确要求直接配置，也应先确认文件权限和密钥不会被提交。
4. 如果模型列表为空、凭据无效、地址不可达，或所有模型的实际请求都失败，则不要新增供应商配置。说明失败原因，并让用户修正 API 地址、API key 或模型权限后重试。
5. 写入后重新加载模型配置，检查供应商下至少一个模型出现在可用模型列表中，并报告供应商名、验证成功的模型 ID 和结果；不要把未验证或失败的模型加入配置。

如果用户没有提供上述信息，当前轮只负责提出具体缺失项；收到信息后再继续配置和验证。
