# Codex 模型状态栏

全局位置：`~/.pi/agent/extensions/codex-status/index.ts`。在 Pi 中执行 `/reload` 启用。

使用 `openai-codex` 时，在现有模型/思考等级后显示，例如：

```text
(openai-codex) gpt-6.1-sol • xhigh · 周剩余 87%（3%） · Token 3.05M（1M）
```

- **周剩余**：读取 ChatGPT 官方 `backend-api/wham/usage`，显示 `100 - used_percent`。按窗口时长（7 天）识别，兼容周额度位于主窗口、次窗口为空的账号。不把 5 小时或 code review 额度当作周额度。
- **Token**：当前会话所有历史条目的累计输入 + 输出 + 缓存 Token，与 Pi 原生统计口径一致；包含会话内历史分支、压缩/摘要及工具报告的模型用量。思考 Token 已包含在输出中，不重复计数。不是全账号每周 Token 总量，也不是当前上下文大小。
- **括号中的消耗**：最近一次完整对话的周额度消耗与 Token 增量。比如从 90% 剩余降至 87%，括号显示 `（3%）`（3 个百分点，不是剩余额度的相对百分比）；累计 Token 从 2.05M 增至 3.05M，显示 `（1M）`。
- 对话起点在首次模型请求之前，终点使用 `agent_settled`，覆盖同次运行中的所有模型调用、工具循环、压缩、自动重试和自动续跑。每次工具调用或低层 `agent_end` 不会提前结算；中止时也统计已经消耗的 Token。对话进行中保留上一次完成对话的括号值，完成后替换；尚未完成过对话时不显示括号。
- 开始时等待一次新鲜额度查询（最多 12 秒，失败后照常运行）；结束时先立即展示本次 Token，再后台查询额度并填入百分比，不阻塞 Pi 回到空闲。对话跨周重置、额度增加、开始或结束查询失败时，百分比括号显示 `（--）`，不编造 0%。
- 启动时后台查询，此后每 60 秒刷新；如果模型响应头已有周额度数据，会直接更新。Token 随消息完成更新。`/codex-status` 手动刷新并显示精确累计及最近完成对话 Token 数；刷新不会改变已经结算的本次消耗。
- 低剩余额度用黄/红色。查询失败显示上次数据并加 `~`（可能过期），没有数据或已过重置时间显示 `--`；失败不会阻止模型运行或弹出通知。手动命令会说明错误。
- 只在交互式 `openai-codex` 模型下启用；切换同 provider 的模型保留括号数据，切换其他 provider 恢复原状。退出、切换会话、`/reload` 时清理轮询和渲染包装；最近对话数据仅保存在当前运行内，重载后从下一次完整对话重新统计。
- 周额度是**账号级**计数，前后差值可能包含其他设备或并发会话的消耗；官方数据有粒度和更新延迟，可能显示 `0%`。它不是把 Token 换算成额度，也不能精确隔离其他进程的额度消耗。

## 实现与兼容性

针对当前 Pi 1.1.0。使用 Pi 的 `modelRegistry.getProviderAuth()` 获取/刷新 OAuth；不自行修改 `auth.json`，不记录凭据。只向固定官方 HTTPS 域名发送额度请求，并禁止重定向。

包装 Pi 导出的 `FooterComponent.render()`，复用原有目录、Git 分支、费用、缓存、上下文和其他插件状态，而不是复制重写整套状态栏。不修改 Pi 安装文件。终端较窄时优先保留模型名称和新指标（标签缩短为 `周`、`T`）。其他插件如果完全替换内置 FooterComponent，需整合该插件的状态栏实现。升级 Pi 后若原生 footer 结构改变，需要重新运行测试。

## 测试

```bash
cd ~/.pi/agent/extensions/codex-status
npm test
```

测试使用模拟登录/网络，不消耗模型 Token、不写登录文件。默认通过 `npm root -g` 找到 Pi；也可设置 `PI_PACKAGE_DIR` 为 Pi 包目录。

卸载：移走 `~/.pi/agent/extensions/codex-status/`，执行 `/reload`。
